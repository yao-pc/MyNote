**CAN 通信**（Controller Area Network，控制器局域网）是一种广泛应用于汽车和工业领域的**串行通信总线协议**。它的核心特点是**多主、差分信号、高可靠性**，最初由德国博世公司于 1980 年代为减少汽车线束而开发。
## 一、基本特点

| 特性   | 说明                                   |
| ---- | ------------------------------------ |
| 拓扑结构 | 总线型，所有节点挂在同一对差分线上                    |
| 通信方式 | 多主（Multi-Master），任意节点可在总线空闲时发送       |
| 传输速率 | 经典CAN最高 1 Mbps；CAN FD 最高可达 8 Mbps 以上 |
| 数据长度 | 经典CAN每帧 0~8 字节；CAN FD 最多 64 字节       |
| 仲裁方式 | 基于标识符的非破坏性位仲裁（ID越小优先级越高）             |
| 错误处理 | CRC校验、应答位、错误帧、错误计数器、总线关闭机制           |
## 二、物理层

CAN 使用**差分信号**：

- **CAN_H** 和 **CAN_L** 两根线
    
- 显性电平（逻辑 0）：CAN_H ≈ 3.5 V，CAN_L ≈ 1.5 V，压差约 2 V
    
- 隐性电平（逻辑 1）：两线都约 2.5 V，压差约 0 V

常用收发器：**TJA 1050、SN 65 HVD 230、MCP 2551** 等。

终端电阻：总线两端各接一个 **120Ω** 电阻，用于阻抗匹配、减少反射。
## 三、帧结构（经典 CAN）

主要有四种帧类型：

1. **数据帧**：发送数据
    
2. **远程帧**：请求数据
    
3. **错误帧**：检测到错误时发送
    
4. **过载帧**：接收方需要延迟
    

**数据帧关键字段：**

text

| 帧起始 | 仲裁段(ID) | 控制段(DLC) | 数据段(0~8 B) | CRC 段 | ACK 段 | 帧结束 |

- **仲裁段**：11 位标准 ID 或 29 位扩展 ID
    
- **控制段**：DLC 表示数据长度
    
- **ACK 段**：接收成功的节点拉低总线表示应答
- 
## 四、仲裁机制
- 
- CAN 最精妙的设计之一：**非破坏性位仲裁**。
- 
- 当多个节点同时发送时：
- 
- - 每个节点一边发送一边监听总线
-     
- - 发送隐性（1）却读到显性（0）的节点，**立即退出仲裁**，转为接收
-     
- - ID 数值越小（二进制前面显性位越多），优先级越高
-     
- - 获胜节点继续发送，**不浪费时间，数据不丢失**
## 五、错误处理

CAN 有五类错误：

- 位错误、填充错误、CRC 错误、格式错误、应答错误
    
每个节点维护两个计数器：

- **TEC**（发送错误计数）
- **REC**（接收错误计数）
    

状态机：

- **错误主动**（Error Active）：正常状态
- **错误被动**（Error Passive）：计数超阈值，发送错误被动帧
- **总线关闭**（Bus Off）：TEC > 255，节点自动脱离总线
    

## 六、CAN FD 与 CAN XL

- **CAN FD**（Flexible Data-rate）：数据段可切换更高速率，数据长度最大 64 字节，CRC 更强
- **CAN XL**：面向更高数据量，最大 2048 字节，速率可达 10 Mbps 以上
    

## 七、典型应用

- **汽车**：ECU 通信、车身控制、动力总成、诊断（OBD-II）
- **工业**：PLC、电机驱动、传感器网络
- **其他**：医疗设备、船舶、电梯控制
